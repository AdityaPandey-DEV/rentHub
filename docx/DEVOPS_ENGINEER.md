## 📄 FILE 1: `.env.local` — Root Environment Variables (Local Development)

```
MONGODB_URI=mongodb://localhost:27017/renthub
```
**Line 1:** **MongoDB Connection String (Local):**
- `mongodb://` — protocol identifier for MongoDB connections
- `localhost` — connects to MongoDB running on the local machine
- `27017` — default MongoDB port
- `renthub` — database name. MongoDB creates it automatically on first write if it doesn't exist
- **In production:** This is replaced with a MongoDB Atlas URI like `mongodb+srv://user:password@cluster0.abc123.mongodb.net/renthub`

```
JWT_SECRET=your_jwt_secret_key_here_change_in_production
```
**Line 2:** **JWT Secret Key:**
- This is the cryptographic signing key for JWT tokens
- Used by `jsonwebtoken` library to sign and verify tokens
- **CRITICAL:** This must be a long, random, unpredictable string in production
- Anyone who knows this secret can create valid tokens for ANY user
- Example production value: `8f3d2a1b-4c5e-6f7a-8b9c-1d2e3f4a5b6c`

```
JWT_EXPIRE=30d
```
**Line 3:** **JWT Token Expiration:**
- Tokens expire after 30 days
- After expiration, the user must login again
- Format: `30d` (30 days), `24h` (24 hours), `60m` (60 minutes)
- Shorter = more secure (less time for stolen tokens to be used)
- Longer = better user experience (less frequent re-login)

## 📄 FILE 5: `client/vercel.json` — Vercel Frontend Deployment Configuration

```json
{
    "rewrites": [
        {
            "source": "/(.*)",
            "destination": "/index.html"
        }
    ]
}
```

**Full File Explanation:**

**Line 2: `"rewrites"`** — Vercel rewrite rules. These modify how Vercel routes incoming requests.

**Lines 3-6: The Rewrite Rule:**
- `"source": "/(.*)"` — matches ANY URL path (regex `(.*)` matches everything)
- `"destination": "/index.html"` — rewrites all requests to serve `index.html`

**Why this is needed (SPA Routing):**
- RentHub is a **Single Page Application (SPA)** — React Router handles navigation client-side
- When a user visits `https://renthub.vercel.app/rooms/123`, Vercel's server doesn't have a file at `/rooms/123` — it only has `index.html`, `assets/index.js`, etc.
- Without this rewrite, Vercel returns 404 for any non-root URL
- With this rewrite, Vercel serves `index.html` for ALL URLs, and then React Router reads the URL and renders the correct component
- This is called **"history mode fallback"** or **"catch-all rewrite"**

**Lines 10-15:** **Development API Proxy:**

## 📄 FILE 10: `server/config/db.js` — MongoDB Connection

```javascript
const mongoose = require('mongoose');

const connectDB = async () => {
  try {
    const conn = await mongoose.connect(process.env.MONGODB_URI);
    console.log(`MongoDB Connected: ${conn.connection.host}`);
  } catch (error) {
    console.error(`Error: ${error.message}`);
    process.exit(1);
  }
};

module.exports = connectDB;
```

**Line-by-line:**
1. Import Mongoose ODM library
2. (blank)
3. Define async connection function
4. Open try block for error handling
5. `mongoose.connect()` establishes connection using the URI from environment variables. `await` pauses until connection is established or fails. In Mongoose 8+, no options like `useNewUrlParser` are needed (they're defaults now).
6. Log success with the host name (useful for verifying you're connecting to the right server — localhost vs Atlas)
7. If connection fails, catches the error
8. Log the error message
9. `process.exit(1)` — crash the app. A running server without a database connection is useless and could cause confusing errors. It's better to fail fast and loudly.
10. Close catch block
11. Close function
12. (blank)
13. Export for use in `server.js`

## 🔧 Deployment Workflow

### Frontend (Vercel) Deployment Steps:

```
1. Developer pushes to GitHub main branch
2. Vercel detects the push (via GitHub webhook)
3. Vercel navigates to `client/` directory (configured in Vercel dashboard)
4. Runs `npm install` to install dependencies
5. Runs `npm run build` (vite build) → generates `dist/` folder
6. Deploys `dist/` contents to Vercel's CDN (edge network)
7. Applies `vercel.json` rewrite rules
8. Site is live at renthub-property-management.vercel.app
```

### Backend (Render) Deployment Steps:

```
1. Developer pushes to GitHub main branch
2. Render detects the push (via GitHub webhook)
3. Render reads `render.yaml` configuration
4. Navigates to `server/` directory (rootDir)
5. Runs `npm install` (buildCommand)
6. Injects environment variables (NODE_ENV, JWT_SECRET, MONGODB_URI)
7. Runs `npm start` → `node server.js` (startCommand)
8. Server starts, connects to MongoDB Atlas
9. API is live at renthub-api.onrender.com
```

### MongoDB Atlas Setup:

```
1. Create account at mongodb.com
2. Create a free M0 cluster (512MB, shared)
3. Set region (e.g., AWS Oregon to match Render)
4. Create database user with password
5. Whitelist IP addresses (0.0.0.0/0 for Render — all IPs)
6. Get connection string: mongodb+srv://user:pass@cluster0.abc123.mongodb.net/renthub
7. Set this as MONGODB_URI in Render environment variables
```

## 📦 Build Process Explained

### Frontend Build (`vite build`):

```
Source Files                    Build Output (dist/)
─────────────                   ──────────────────
src/main.jsx          ──┐
src/App.jsx            ─┤
src/pages/*.jsx        ─┤──▶   dist/assets/index-[hash].js    (minified JS bundle)
src/components/*.jsx   ─┤──▶   dist/assets/index-[hash].css   (minified CSS)
src/context/*.jsx      ─┘──▶   dist/index.html                (HTML with script tags)

index.css              ──────▶  CSS processed through TailwindCSS
                                (unused utility classes removed = tree-shaking)
```

**Key optimizations:**
- **Code Splitting:** Vite automatically splits code by routes (lazy loading)
- **Tree Shaking:** Removes unused JavaScript and CSS
- **Minification:** Removes whitespace, shortens variable names
- **Content Hashing:** File names include hashes (e.g., `index-a1b2c3d4.js`) for cache busting — browser caches are invalidated only when file content changes.

### Backend (No Build Step):

```
Node.js runs the source files directly (no compilation needed).
`npm install` downloads dependencies, `node server.js` starts the app.
```

## 🔑 Key DevOps Concepts Summary

### 1. Monorepo Structure
Both frontend and backend live in ONE Git repository. Each deployment platform targets a specific subdirectory (`client/` or `server/`).

### 2. Environment Separation
Dev (`.env.local`), production (`.env.production`, Render/Vercel env vars). Never mix environments.

### 3. Static vs Dynamic Hosting
- **Vercel (Static):** Serves pre-built HTML/JS/CSS files from CDN edge nodes. No server-side processing.
- **Render (Dynamic):** Runs a Node.js process that handles requests in real-time. Maintains WebSocket connections.

### 4. SPA Routing
The `vercel.json` rewrite rule is essential — without it, refreshing any page except `/` would return 404.

### 5. Infrastructure as Code
`render.yaml` and `vercel.json` define infrastructure declaratively. Changes to infrastructure are tracked in Git alongside code.
